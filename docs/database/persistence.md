# Persistence / Persistencia

## Overview / Visión general

EN: PostgreSQL is the primary database. Prisma is the persistence layer. The
Prisma client is only imported from the **infrastructure** layer; the domain never
sees it (AGENTS.md sections 12 and 13).

ES: PostgreSQL es la base de datos principal. Prisma es la capa de persistencia.
El cliente Prisma solo se importa desde la capa de **infraestructura**; el dominio
nunca lo ve (AGENTS.md secciones 12 y 13).

```
Next.js ─▶ HTTP ─▶ NestJS ─▶ Application ─▶ Domain ─▶ Infrastructure(Prisma) ─▶ PostgreSQL
```

## Schema / Esquema

EN: Four models: `Project`, `Experience`, `Skill`, `ContactMessage`. Each maps to a
snake_case table via `@@map` (for example `ContactMessage` → `contact_messages`).
Column names use `@map` where needed (`start_date`, `end_date`, `created_at`,
`updated_at`).

ES: Cuatro modelos: `Project`, `Experience`, `Skill`, `ContactMessage`. Cada uno
mapea a una tabla snake_case mediante `@@map` (por ejemplo `ContactMessage` →
`contact_messages`). Los nombres de columna usan `@map` cuando hace falta
(`start_date`, `end_date`, `created_at`, `updated_at`).

## Migrations / Migraciones

EN: Migrations are versioned at the repository level and applied with the Prisma
CLI, which reads `apps/api/prisma7.config.ts`. Do not edit or delete applied
migrations (AGENTS.md section 14).

ES: Las migraciones se versionan a nivel de repositorio y se aplican con el CLI de
Prisma, que lee `apps/api/prisma7.config.ts`. No editar ni borrar migraciones ya
aplicadas (AGENTS.md sección 14).

Commands / Comandos:

```bash
# EN: generate the Prisma client into src/generated/prisma
npm run db:generate --workspace @cantantes/api

# EN: create a new migration locally (requires a running database)
npm run db:migrate --workspace @cantantes/api

# EN: apply pending migrations (deployment)
npm run db:migrate:deploy --workspace @cantantes/api
```

> EN: The migration `20261010120000_add_experience_skill_contact` was authored by
> hand because the local database (Docker) was unavailable when the schema
> changed. Its SQL matches the `prisma migrate diff` output and `prisma migrate
> deploy` records and applies it like any generated migration. It is **pending**
> until a database is reachable.
>
> ES: La migración `20261010120000_add_experience_skill_contact` se redactó a mano
> porque la base de datos local (Docker) no estaba disponible cuando cambió el
> esquema. Su SQL coincide con la salida de `prisma migrate diff` y `prisma
> migrate deploy` la registra y aplica como cualquier migración generada. Está
> **pendiente** hasta que haya una base de datos accesible.

## Mapping / Mapeo

EN: Each repository maps rows ⇄ aggregates:

- `toDomain` / `toExperience` / `toSkill` re-validate **every** invariant by
  calling the aggregate factory. A corrupt row fails loudly instead of leaking.
- `PrismaProjectRepository` also has `toColumns` for the write path (currently
  unreachable over HTTP).
- `PrismaContactMessageRepository.save` writes one row per message.

ES: Cada repositorio mapea filas ⇄ agregados:

- `toDomain` / `toExperience` / `toSkill` re-validan **cada** invariante llamando a
  la fábrica del agregado. Una fila corrupta falla de forma ruidosa en lugar de
  filtrarse.
- `PrismaProjectRepository` también tiene `toColumns` para el camino de escritura
  (hoy inalcanzable por HTTP).
- `PrismaContactMessageRepository.save` escribe una fila por mensaje.

## Connection handling / Manejo de conexión

EN: `PrismaService.onModuleInit` connects on boot. A failed connection is
**non-fatal**: it logs a warning so the API still boots and `GET /api/health` can
report `503 degraded` instead of the process crashing.

ES: `PrismaService.onModuleInit` conecta al arrancar. Una conexión fallida es **no
fatal**: registra una advertencia para que la API igualmente arranque y
`GET /api/health` pueda reportar `503 degraded` en lugar de que el proceso falle.

## Environment / Entorno

EN: `DATABASE_URL` comes from the repository-root `.env`, which is git-ignored and
shared with `docker-compose.yml`. Never commit credentials.

ES: `DATABASE_URL` proviene del `.env` en la raíz del repositorio, que está
ignorado por git y se comparte con `docker-compose.yml`. Nunca comprometas
credenciales.
